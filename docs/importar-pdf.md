# Import a resume from PDF

For users who have a resume in PDF but no backup. **Backup → Import resume from PDF** reads the file in the browser, fills the fields and creates a **new** resume after a review screen. No existing resume is changed, nothing is sent anywhere and no AI is used.

Code: `src/features/pdf-import/`.

## How it works

1. **Extraction** (`extractPdf.ts`, with `pdfjs-dist`): the text of each page, grouped into lines, with font size, bold and italic, position, and the real address of each link (PDF link annotations) with the text shown on it.
2. **Reading** (`parseResume.ts`, pure and tested): turns the lines into resume data.
   - **Sections** are recognized by their titles, in Portuguese and English, with common synonyms ("Perfil", "Resumo", "Experiência profissional", "Formação", "Habilidades", "Idiomas", "Skills", "Education"...).
   - **Header** (everything before the first section): the largest line is the name; the line right after it, or a larger one, is the job title; e-mail, phone and links are found by their format, also when they share one line separated by `|` or `•`; what is left is the address.
   - **Links**: LinkedIn, GitHub and one more site (portfolio). When the visible text is not the address itself, it becomes the link's display name.
   - **Entries** (experience, education, projects, references) start at lines with a larger font; without that, at bold lines; without that, at date lines ("Jan 2020 - Atual", "2016 - 2020", "Maio de 2030", also at the end of a line such as "Company | 2018 - 2020"). "Atual", "Presente", "Current" become an empty end date.
   - **Wrapped lines** are joined back: a line that fills the width followed by a close line of the same style continues the same paragraph.
   - Leading bullets (`•`, `-`, `▪`...) are removed.
3. **Review** (`ImportPdfModal.tsx`): the resume name (the person's name by default), what was found in each field, and the text that did not go into any field, so it can be copied by hand.

The extraction and the reader are loaded only when the user imports a file (`importResumePdf.ts`, dynamic import), so `pdfjs-dist` is not part of the initial download.

## PDFs generated by this app

The layout is known, so every field comes back: contact, links with display names, profile, experiences, education, projects (technologies, dates and link), skills, languages, soft skills, interpersonal competencies and references. A test generates the PDF with `CVDocument` in Portuguese and English, reads it back and compares each field (`roundTrip.test.tsx`).

## Other layouts

Best effort. Single-column resumes with clear section titles work well. Known limits:

- Two-column layouts can mix the columns.
- Education reads the first line as the institution and the second as the course (this app's order); other resumes may use the opposite order.
- Sections the app does not have (certifications, courses, awards...) are listed as text that did not go into any field.

## Errors

- Not a PDF, or a damaged file: "The file could not be opened".
- PDF with a password: asks for a copy without the password.
- PDF without text (scanned image): explains that there is nothing to read. There is no OCR.
